# Пользовательская инструкция Changan Service Monitor

Инструкция рассчитана на Changan UNI-S / CS55 Plus с уже включённым ADB по Wi‑Fi.
Приложение подключается к локальному endpoint `localhost:5555` и использует shell
только для предусмотренных read-only операций.

## Режимы экрана

Приложение автоматически использует подходящую форму интерфейса:

- на телефоне — последовательная portrait-разметка;
- на широком landscape-экране ГУ — двухпанельная разметка с отдельными областями статуса, графика, ADB и настроек.

Ручное переключение режима не требуется. Android выбирает разметку по текущей ориентации и конфигурации экрана. При повороте телефона landscape-разметка также будет применена.

## 1. Первый запуск

Интерфейс автоматически выбирает разметку по ориентации экрана. На широком
landscape-экране головного устройства используются две прокручиваемые панели:
слева — статус, Health, история и экспорт; справа — ADB Wi‑Fi и параметры
мониторинга. На телефонном portrait-экране остаётся последовательная прокрутка
одной колонкой.

1. Установите APK на головное устройство.
2. Откройте **Changan Service Monitor**.
3. Проверьте, что в блоке ADB указан endpoint `localhost:5555`.
4. Убедитесь, что ADB Wi‑Fi на ГУ был включён заранее.

![Главный экран приложения](screenshots/main-screen.svg)

На главном экране также находятся параметры пробега и интервал ТО.
Моточасы временно отключены до подтверждения свойства в потоке данных ГУ.

## 2. Сохранение пароля ADB

1. Введите пароль в поле **Пароль ADB Wi‑Fi**.
2. Нажмите **Сохранить пароль ADB**.
3. После сохранения пароль можно удалить из поля — приложение использует сохранённую
   конфигурацию.

Пароль сохраняется в отдельном файле приватного каталога приложения
`files/adb_wifi_config.enc`. Файл шифруется AES-GCM с ключом Android Keystore;
при подключении он передаётся только через stdin процесса `adb shell` и не попадает
в аргументы shell-команд или журнал.

## 3. Проверка подключения

1. Нажмите **Подключить ADB shell**.
2. Дождитесь изменения статуса под endpoint.
3. Успешный результат отображается как **ADB Wi‑Fi: shell подключён**.

Сначала приложение выполняет `adb connect localhost:5555` без секрета. Затем
прошивка может запросить пароль при запуске `adb shell`; сохранённый пароль
передаётся только этому процессу через stdin. Это особенность прошивки ГУ.

![Статус подключённого ADB shell](screenshots/adb-connected.svg)

При ошибке проверьте:

- ADB Wi‑Fi действительно включён на ГУ;
- endpoint `localhost:5555` доступен локально;
- приложение установлено с необходимыми root/privileged правами;
- пароль сохранён повторно после изменения настроек.

## 4. Настройка мониторинга

1. Откройте **Настройки**.
2. Оставьте включённым переключатель **Мониторинг включён** — он управляет фоновыми read-only проверками.
3. Укажите **Интервал ТО, км** — расстояние между обслуживаниями.
4. Укажите **Предупреждать за, км** — порог показа предупреждения.
5. При необходимости настройте период проверки, уведомления, тихие часы и расширенный журнал.
6. Для запуска после перезагрузки включите отдельный переключатель **Автозапуск приложения при загрузке ГУ**.
7. Нажмите **Сохранить настройки**.

Мониторинг включён по умолчанию. При его отключении фоновые проверки и автоматические
предупреждения прекращаются, но ручная кнопка **«Обновить пробег»** остаётся доступной.
Автозапуск приложения после загрузки запускает мониторинг только если переключатель
мониторинга включён.

Поля начального/текущего пробега в настройках нет намеренно: приложение не позволяет
случайно сбить показание или базу интервала вручную.

Новая база межсервисного интервала создаётся только через **Журнал ТО**. Пробег
последней сохранённой записи ТО плюс заданный интервал образуют следующий срок обслуживания.
Если записей нет, приложение показывает «Базовое ТО не задано».

## 5. Обновление приложения

При каждом запуске Changan Service проверяет подписанный manifest в публичном release-репозитории. Проверку
можно повторить вручную кнопкой **«Проверить обновления»**. В этом разделе отображается
текущая версия приложения; при наличии новой версии показываются обе версии.
При наличии новой версии
появляется диалог с выбором:

- **«Позже»** — отказаться от обновления и продолжить работу в текущей версии;
- **«Скачать и установить»** — скачать APK и открыть штатный установщик Android.

После загрузки APK приложение не устанавливает его скрытно: установку подтверждает
системный установщик. Если прошивка запрещает установку APK из этого источника,
приложение предложит открыть системное разрешение. После выдачи разрешения повторите
проверку и установку. Для проверки нужен интернет; при автоматической сетевой ошибке
мониторинг всё равно продолжает запускаться. После возврата из системного установщика
скачанный APK удаляется; старые APK и незавершённые временные файлы очищаются перед
следующей загрузкой.

Если появляется сообщение о несовпадении сертификата, текущая установка подписана
другим ключом — обычно это старая debug-сборка. Android не разрешает обновлять APK
с другой подписью. Экспортируйте данные, установите текущий стабильный APK вручную
один раз и дальше используйте штатный updater. В сообщении об ошибке и в логе
статусов отображаются отпечатки обоих сертификатов для проверки.

## 6. История, Health и экспорт

- При запуске ADB проверяется автоматически. Зелёный статус означает успешный shell probe,
  красный — ошибку подключения; подробности доступны в **«Показать лог статусов»**.
- Блок **Health** показывает явную строку пробега, источник, качество и возраст последнего показания, а также
  состояние локального ADB endpoint.
- Кнопка **«Показать лог статусов»** открывает журнал ADB, Health и updater. Из окна его
  можно прочитать или экспортировать.
- График отображает накопленную локальную историю показаний за последние 30 дней.
- **Экспорт CSV** и **Экспорт JSON** открывают системное меню передачи файла.
- **Журнал ТО** сохраняет дату, пробег и работы локально; дата вводится или выбирается
  календарём в формате `ДД.ММ.ГГГГ`.
- В истории журнала можно выбрать **«Изменить»** или **«Удалить»** у старой записи.
  После изменения последняя запись по дате снова используется как база следующего
  межсервисного интервала.
- **Сбросить интервал** в журнале создаёт новую базовую запись обслуживания, которая
  сохраняется после перезапуска приложения.
- История и журнал доступны без интернета.

## 7. Безопасность и ограничения

### Где хранятся обновления

Релизы публикуются в открытом репозитории
[`Changan-Service-Release`](https://github.com/sunsatana/Changan-Service-Release).
Приложение получает manifest, APK и checksum по HTTPS/443. Исходный код остаётся в
приватном репозитории, а GitHub token и приватный ключ подписи хранятся только в
GitHub Actions Secrets.

Если manifest недоступен, локальный мониторинг продолжает работать. Для аварийного
обновления можно вручную установить APK из раздела Releases публичного репозитория.

### Если приложение не запускается

При ошибке ранней инициализации приложение показывает аварийный экран вместо
немого закрытия. На нём отображается краткая причина, а нажатие на экран открывает
системное меню отправки диагностического журнала. Выберите удобный способ передачи
файла и сохраните его для анализа.

Если основной экран успел открыться, используйте кнопку **«Экспорт журнала запуска»**.
Журнал находится в `files/diagnostics/startup.log`, содержит этапы старта и полный
stack trace необработанного исключения. Если ошибка произошла в фоне мониторинга,
мониторинг останавливается, а причина записывается в тот же журнал; остальные разделы
приложения остаются доступными. Пароль ADB и токены в журнал не записываются.

- ADB Wi‑Fi должен быть включён до запуска проверки из приложения.
- Приложение использует локальный endpoint и не принимает произвольные shell-команды
  из пользовательского интерфейса.
- Получение пробега через Vehicle HAL требует privileged-доступа и разрешения
  `android.car.permission.CAR_MILEAGE`; обычной установки APK может быть недостаточно.
- Не публикуйте файл `adb_wifi_config.enc`, резервные копии каталога приложения или
  APK вместе с извлечёнными секретами.
- Моточасы временно не читаются и не вычисляются: они отключены в backend и UI до
  подтверждения конкретного свойства прошивки.

Подробности интеграции и сборки находятся в [README](../README.md),
а инструкция privileged-установки — в [PRIVILEGED-INSTALL.md](PRIVILEGED-INSTALL.md).
